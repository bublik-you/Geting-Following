# Каркас второй презентации

Проект находится целиком в `presentation-2/`. В нём собственные TypeScript, Vite, зависимости, стили, материалы и офлайн-кэш. Список сцен пока пуст.

## Запуск и сборка

Используйте Node.js 24, как в GitHub Actions. Выполните из корня репозитория.

```sh
npm --prefix presentation-2 ci
npm --prefix presentation-2 run dev
```

Откройте адрес, который выведет Vite. Для проверки офлайн-кэша соберите проект и запустите предварительный просмотр.

```sh
npm --prefix presentation-2 run build
npm --prefix presentation-2 run preview
```

| Файл или папка | Назначение |
| --- | --- |
| `src/main.ts` | Контейнер сцены, переключение и отмена действий при уходе со сцены |
| `src/scenes/index.ts` | Тип сцены и порядок показа |
| `src/style.css` | Базовые стили второй презентации |
| `public/` | Локальные изображения, шрифты и медиа |
| `scripts/cache-build.mjs` и `scripts/worker.js` | Список ресурсов, версия и обслуживание офлайн-кэша |
| `dist/` | Готовая сборка второй презентации |

## Как добавить сцену

1. Создайте модуль в `src/scenes/`, например `opening.ts`.
2. Экспортируйте объект типа `Scene`. В `mount(container, signal)` создайте разметку и добавьте её в контейнер. Заголовок из `title` используется как доступное имя области.
3. Импортируйте объект в `src/scenes/index.ts` и добавьте его в массив `scenes`. Порядок массива задаёт порядок показа. При добавлении второй сцены появятся кнопки «Назад» и «Далее».
4. Поместите изображения, шрифты и медиа в `public/`. Формируйте путь от базы проекта, например `${import.meta.env.BASE_URL}images/cover.webp`. Можно также импортировать файлы из `src/` через Vite. Оба варианта попадают в офлайн-сборку.

Для CSS-анимаций добавьте правила в стили проекта. Класс `scene-motion` отключает CSS-анимации и переходы при системной настройке уменьшенного движения. Для анимации из TypeScript можно использовать Web Animations API. При смене сцены проигрывание можно остановить по её сигналу.

```ts
if (!matchMedia('(prefers-reduced-motion: reduce)').matches) {
  const motion = element.animate(
    [{ opacity: 0 }, { opacity: 1 }],
    { duration: 300, fill: 'both' },
  );
  signal.addEventListener('abort', () => motion.cancel(), { once: true });
}
```

Используйте этот же `signal` в обработчиках событий через `addEventListener(..., { signal })`. Таймеры и циклы кадров очищайте при `abort`.

## Публикация и офлайн-режим

После объединения ветки GitHub Actions соберёт проекты независимо и упакует их в один сайт.

- «4 кота — Бизнес-разведка» доступна по прежнему адресу https://bublik-you.github.io/Geting-Following/
- Вторая презентация получит адрес https://bublik-you.github.io/Geting-Following/presentation-2/

Открывайте обе страницы по адресам со слешем в конце. Для первого посещения второй презентации используйте именно адрес папки. Прямая ссылка на `presentation-2/index.html` может открыть «4 кота», если браузер пока находится под управлением её существующего service worker.

Для каждой презентации один раз откройте её страницу с интернетом и дождитесь статуса «Готово офлайн». Затем проверьте повторное открытие в том же браузере после отключения сети. Вторая презентация регистрирует service worker в области `/Geting-Following/presentation-2/` и обновляет кэш только своего проекта. У первой остаются её прежний worker, кэш и автономный архив. Добавляйте в новую презентацию локальные ресурсы, чтобы она могла работать без внешних CDN и API.

Собранный сайт можно проверить локально. Выполните из корня, предварительно установив зависимости обеих презентаций.

```sh
npm run build
npm --prefix presentation-2 run build
npm --prefix presentation-2 run assemble:pages
npm --prefix presentation-2 run test:pages
```

Итоговый сайт находится в `presentation-2/pages-dist/`. Для ручной проверки откройте его командой `npm --prefix presentation-2 run preview:pages`. В тестах можно задать `CHROMIUM_PATH` для установленного Chrome или Chromium.
