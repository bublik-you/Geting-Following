# Как заполнить презентацию

Изменения в текстах и цифрах собираются автоматически при запуске Vite. Для опубликованной версии выполните `npm run build` после правок и опубликуйте новую сборку.

## Содержание

Данные находятся в `src/data/content.ts`. Для незаполненного текста оставьте `''`, для отсутствующего числа используйте `null`. Число `0` отображается как введённый результат.

| Что изменить | Где в файле |
| --- | --- |
| Имена, роли, задачи и участие | `team`. Первый элемент принадлежит рассказчику |
| Адреса и фотографии заведений | `venues.burger` и `venues.tea` |
| Описание, цель, окно наблюдений и недельные задачи | `research.burger.context` и `research.tea.context` |
| Метод | `method` в данных нужного заведения |
| Портрет, альтернативы, критерии успеха | `portrait` |
| Истории клиента | `jobs`. Добавьте от 3 до 5 записей |
| Этапы и моменты истины | `journey`. Название этапа хранится в `label`, подробности в `fields` |
| Воронка и сравнение | `metrics`. Поле `value` принимает число. Сохраните порядок метрик, подписи и единицы при заполнении обоих наборов |
| Наблюдения и подтверждения | `observations`. Добавьте от 3 до 5 записей. `point` допускает `null` или координаты `{ x, y }` от 0 до 100 в процентах от ширины и высоты схемы |
| Матрица рекомендаций | `recommendations`. Добавьте от 5 до 7 записей. `effect` и `effort` принимают целые оценки от 1 до 5. Без обеих оценок запись появится только в списке |
| Быстрые победы | `quickWins`. Добавьте 2–3 записи. `hour` задаёт положение на шкале от 0 до 48 часов |
| Допущения и риски | `risks` |
| Три ключевых вывода | `conclusions`. Они также попадут в печатное резюме |
| Executive summary | `summary`. Краткий текст по каждому полю помогает уместить резюме на одной странице A4 |
| Приложения | `appendix` |

`researchTemplate()` создаёт отдельный набор для каждой точки. Индивидуальные правки внесите после объявления `research`. Например, направление правки видно из этой строки.

```ts
research.burger.context[1].value = ''; // Цель Burger King
```

У всех записей `Field` поле `label` отвечает за заголовок, а `value` за содержимое. При заполнении метрик проценты указывайте по шкале 0–100, время указывайте в минутах. Значения воронки берутся из первых двух строк, визитов и покупок. Сравнение выводит введённый показатель для каждой точки в одинаковых единицах.

## Фото, спрайты и звук

Положите материалы в `public/media/`. В полях данных указывайте путь относительно этой папки, например `burger/front.webp`.

- `burger/`, `tea/` — фото заведений. Поле `photo` в `venues` меняет превью на карте и фото в сцене.
- `team/` — портреты и спрайты. Укажите портрет в `team[n].photo`. Чтобы изменить внешность персонажа на карте, подготовьте по портрету пиксельный PNG с прозрачным фоном 16 × 26 px и укажите `team[n].avatar`. Первый спрайт используется также в диалогах.
- `observations/` — фото для поля `photo` у наблюдения, `screenshots/` — скриншоты, `extra/` — приложения и дополнительные файлы.
- В `media` можно добавить те же фото для показа в медиатеке. У каждой записи задайте `file` и `alt`.
- Для вложения в раздел приложения укажите `appendix[n].file` и при необходимости `text`. Храните в репозитории только согласованные к публикации изображения и обезличенные материалы.
- `audio/` — записи докладчика. В `src/story.ts` заполните у реплики `text` и добавьте `audio: 'audio/имя.mp3'`. Пустой путь оставляет звуки «мимими». Кнопка звука управляет обоими вариантами.

## План защиты

В `src/story.ts` массив `chapters` хранит 13 разделов. Заполните `lines` для облачков и `notes` для отдельного окна. При добавлении реплик в облачке появятся кнопки переключения. `seconds` задаёт длительность по плану. При перераспределении времени сохраните сумму 420 секунд.

Чтобы проверить работу без сети, откройте production-сборку на HTTPS или localhost, дождитесь загрузки и затем перезагрузите страницу с отключённой сетью. Через локальный сервер со статическими файлами интернет для показа не требуется.
