# Дерево коммуникаций

Интерактивная пиксельная презентация «Влияние социальных сетей на корпоративные коммуникации». 18 последовательных сцен, один рассказчик и непрерывный мир дерева. Содержание — около 986 слов: ориентир 7–8 минут при чтении вслух с короткими паузами; темп переходов задаёт зритель.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.22.1).

```sh
cd /workspace/Geting-Following
npm ci
npm run dev -- --port 5173
```

Откройте адрес, который Vite напечатает в терминале, в своём браузере. Для выступления предпочтителен альбомный экран планшета или 16:9. Кнопка в правом верхнем углу включает полный экран, если браузер разрешает его. Сервер не требует ключей, базы данных или внешних сервисов. После сборки приложение использует только собственные файлы, без CDN, внешних шрифтов и трекеров.

Облачные задачи уже изолированы: работайте в существующем checkout, дополнительный Git worktree не нужен. Процессы сервера не сохраняются при восстановлении среды — запускайте `npm run dev` заново.

## Управление

- Касание, клик, →, пробел или Enter: допечатать реплику; следующее нажатие — новая сцена.
- Во время перемещения повторные нажатия игнорируются. Автоматического перехода после реплики нет.
- ← или кнопка назад: предыдущая сцена.
- Home или кнопка круговой стрелки: первая сцена.
- M: выключатель звука (выбор сохраняется локально).
- F: полный экран.

Все звуки синтезируются Web Audio API после пользовательского жеста. Отказ браузера в аудио или полном экране не блокирует презентацию. Системная настройка уменьшения движения ускоряет перемещения.

## Редактирование

- `src/story.ts`: русские реплики, заголовки, координаты и характер действия каждого эпизода.
- `src/world.ts`: процедурная пиксельная графика Phaser 3, персонаж, окружение и перемещения камеры. Графика не является набором картинок-слайдов.
- `src/main.tsx`: интерфейс React, печать текста, клавиатура и сенсорное управление.
- `src/cosmos.ts`: кадры нового персонажа, космический фон, связи тем и анимированная сингулярность.
- `src/audio.ts`: синтез речи-имитации и коротких эффектов.
- `src/style.css`: диалоговые облачка и адаптивная вёрстка.

Герой перерисован по приложенному образцу: коричневая остроконечная шляпа, бирюзовая мантия, рюкзак и посох. Все позы создаются программно в `makeWizardTextures()` в `src/cosmos.ts`. Космическая палитра и туманности основаны на втором приложенном пейзаже; готовые иллюстрации фоном не подставляются. В финале герой подлетает к общему центру, линии всех тем закручиваются в спираль и несут светящиеся частицы к ядру. При возврате или перезапуске мир восстанавливается; уменьшение движения в настройках системы показывает спокойный вариант финала.

## Проверка

```sh
npm run build
npm test
```

Браузерные тесты используют установленный Chromium (`/usr/bin/chromium`). На другой машине укажите `CHROMIUM_PATH` с путём к Chromium/Chrome или установите браузер Playwright и передайте его путь через эту переменную. После `npm run build` тесты сами запускают production preview на порту 4173 и проверяют путь `/Geting-Following/`. В CI используется Chromium, установленный Playwright; локально можно указать `CHROMIUM_PATH`. Проверяются все 18 эпизодов, допечатывание, блокировка переходов, возврат, перезапуск, звук и границы текста на экранах 1024×768, 1280×720, 800×1280 и 390×844. Это эмуляция браузером, не испытание на физическом Android-устройстве.

## Сборка и размещение

```sh
npm run build
npm run preview -- --port 4173
```

Каталог `dist/` готов для статического хостинга с HTTPS (например, GitHub Pages, Cloudflare Pages или Netlify). Команда сборки — `npm run build`, выходной каталог — `dist`. Базовый путь Vite — `/Geting-Following/`, включая favicon и JS/CSS. При размещении под другим адресом измените `base` в `vite.config.ts`. Большой файл движка Phaser ожидаем; он отделён от кода презентации и кэшируется отдельно.

## Автоматическая публикация GitHub Pages

Workflow `.github/workflows/deploy.yml` запускается после каждого push в `main` или вручную через Actions → Deploy presentation to GitHub Pages → Run workflow. Он устанавливает зависимости из lockfile, собирает сайт, проверяет production-сборку в Chromium, загружает `dist` как Pages artifact, публикует его и повторно проверяет все сцены и звук по выданному GitHub HTTPS-адресу. Ошибки ресурсов, сцен или звука делают проверку неуспешной.

Однократно в Settings → Pages → Build and deployment → Source выберите **GitHub Actions**. Если требуется, включите Actions для репозитория и разрешите официальные actions в Settings → Actions → General. Публикация использует встроенный `GITHUB_TOKEN` с правами `pages: write` и `id-token: write` только у задания deploy; добавлять собственные ключи в код не нужно. Доступность Pages для закрытого репозитория зависит от тарифа GitHub; видимость репозитория workflow не меняет.

Ожидаемый адрес: `https://bublik-you.github.io/Geting-Following/`. Фактическую ссылку выдаёт задание Deploy website в окружении `github-pages`. Успешным окончанием проверки считается зелёное задание **Verify live HTTPS website**, а не только завершение сборки.

Для ручной проверки опубликованной версии:

```sh
PLAYWRIGHT_BASE_URL=https://bublik-you.github.io/Geting-Following/ npm test
```
